## Resilience

- **An error is contained where it happens** — a tab or tool window
  that fails shows *This tab hit an error* or *This tool window hit an
  error* with **Retry**, **Close tab** or **Hide window**, and the rest
  of the tab keeps working; a failed tab's close guard no longer offers
  a Save it cannot make. An error the tab cannot recover from shows one
  page in the app's theme — *Reload to continue — your data is safe* —
  with **Reload** and **Copy details** (a green check confirms the
  copy). The web tab contains failures and reports nothing: the server
  surfaces stay hard-off, so there is no switch because there is no
  channel.

## Help

- **Report Issue and Feature Request** — Settings › About › Support
  gains **Report…** and **Request…**: a dialog with a title and one
  description (the steps to reproduce for a bug, the workflow and the
  behavior you would like for a feature; Markdown welcome).
  **Preview on GitHub** opens a new issue with the title and one
  composed body; nothing is posted until you submit it there. The
  system facts are not available on this host, so the dialog says to
  fill in the version and platform on GitHub. The notification
  timeline's **Bug Report or Feature Request** card opens the same
  dialog, and a **Community Chat** card replaces the website nudge.
- **The diagnostic bundle** — Settings › Data › Diagnostics gains
  **Diagnostic Bundle › Save bundle…**: one ZIP with the status
  snapshot, your settings and every other part a served tab can
  gather, downloaded like any file and sent nowhere; its README names
  the parts this host cannot answer.

## Fixes

- **JSON diagnostics wait for the JSON mode** — the first validation of
  a JSON body no longer runs before the language mode is set up, so the
  first pass is never rejected.
- **In-app docs** — two diagrams with a blinking terminal cursor kept
  the tab repainting while the Docs tab was shown; the cursors are
  static.
