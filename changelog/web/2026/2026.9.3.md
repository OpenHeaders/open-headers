## Requests run from the tab

- **The tab is the request's context** — an HTTP or GraphQL send, a
  WebSocket or MQTT session and a GraphQL subscription are resolved in
  the tab — variables, the environment, secrets, cookies and the
  pre-request script — and the serving server opens the connection and
  streams the raw response or frames back; the post-response script,
  cookie capture and the saved response happen in the tab. gRPC is
  sent by the server and resolved there. The place chip beside
  **Send**, **Connect** and **Invoke** says so, and every response and
  timeline carries **Sent from** on its meta strip.
- **Scripts run in the tab** — pre-request and post-response scripts
  run in the tab's own sandboxed Safe runtime: the `oh.*` script API
  only, no filesystem, no process access, no module loader. A browser
  tab has no Developer mode, so the Settings tab states *Safe mode* as
  a fact rather than offering a choice, and each run records the mode
  on the response. The sandbox is part of the app itself, so an
  offline tab runs its scripts too.
- **Runs on** — the request's Settings tab and every folder's and
  collection's settings carry the *Runs on* row, and **Settings › API
  Requests › HTTP › Execution place** the global one; the values sync
  with the workspace as roles and resolve here.

## Approving a device sign-in

- **The consent card** — when the extension, the desktop app or
  `oh login` signs a person in, the browser lands on a card in the web
  app: the product mark over it, *the browser extension* / *the
  desktop app* / *the command-line tool* *would like to sign in to
  this server*, one line on what allowing means, a primary **Allow**
  over a quiet **Decline**, and the signed-in person under them with
  **Switch account**. A device sign-in from the command line names the
  device and shows the code — check that it matches the one your
  device shows.
- **Signed in or not** — a browser already signed in approves in one
  click; one that is not sees the usual sign-in first — the password
  form or the identity provider's button — and comes back to the card
  on the same decision. Switching account drops the session, draws
  the gate and returns to the same card.
- **A decision ends where the client waits** — Allow sends the browser
  back to the desktop app's or the extension's return address, and
  Decline does the same carrying the refusal, so the window the client
  opened closes on a no as on a yes; a command-line sign-in settles on
  the card with *Device approved* or *Sign-in denied*. An expired or
  unknown request says so and points back at the device.

## Server Admin

- **The claim lands on Users** — the operator's first arrival after
  claiming the server opens **Server Admin › Users** with the tool
  window beside it, once; the gate's button reads *Continue to Server
  Admin*.
- **The setup code is asked only where the claim demands it** — a
  browser on the server's own machine draws no code field; a remote
  one must fill it, and the hint says where the code is printed.
- **Users sign in with their email** — creating a user takes an email
  and, on a server whose login is the password, an initial password;
  **Set email** on a user's row repairs one admitted without, and the
  password action waits on the email and says so.
- **Audit** — a *Device sign-in* event per device a person approves,
  with the person as actor, and its filter option.
- **Server tab** — shows the build's version and, for a build that
  ships no notes, says so instead of a blank tab.

## Settings and fixes

- **Proxy is a root of its own** — it sits after Backup and Sync in
  the settings tree; the Connectivity wrapper that held it alone is
  gone. Page ids and deep links are unchanged. The *Where they go* row
  hides while there is only one place.
- **Synced with reads Connected** — the served server's row on the
  Sync page said *Connecting…* over a synced wire.
- **Enter submits from every field** — the password form's email
  field and the setup form's name, email and password fields did
  nothing on Enter unless the caret sat in the last field.
