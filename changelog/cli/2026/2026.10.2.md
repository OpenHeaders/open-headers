## Crash and error reports

- **A failure nothing caught is reported, then the command ends the
  way it always did** — the message on stderr and exit code 1, after
  the report is recorded and the capped exit flush; with the channel
  off nothing is recorded and the exit is immediate. A report carries
  what kind of error it was and where in `oh`'s own code it happened —
  error class names, template ids (which standard engine message it
  matched, never its text) and positions in the binary's own files —
  never the message, an argument, a path or a URL, because every string
  on the channel must match a fixed grammar. No install identifier: the
  invocation's random session id, shared with usage counting, is all
  that groups it.
- **One more switch** — `errorReports` in `cli.json`, independent of
  `telemetry`; `OH_TELEMETRY=0` (or `false`, `off`) silences both
  channels. The terminal stays quiet either way; the privacy policy
  (effective October 19, 2026) and the wire-transparency document
  carry the envelope and the grammar table.

## Usage counting

- **Two coarse facts join the envelope** — the binary's CPU
  architecture and the operating-system major (macOS 15, Windows 11;
  Linux stays unstamped), never a build number.
