## Usage counting

- **The outbox** — an envelope the wire did not confirm within the exit
  flush is sealed exactly as it was, in `telemetry-outbox.json` beside
  `cli.json`, and the next invocation delivers it at boot before its
  own session starts. At most eight entries wait, oldest first, each
  tried at most five times; one invocation learns the network is down
  once and seals the rest without trying, so an offline command waits
  one cap, never one per envelope. A shape the service refuses is
  dropped. Turning `telemetry` or `errorReports` off discards that
  channel's sealed entries at once, and `OH_TELEMETRY=0` empties the
  file. The exit flush now allows 1.5 seconds, sized from the measured
  round trip, instead of half a second that confirmed nothing on a cold
  connection.
- **The install-state block and a send event** — every envelope
  carries coarse facts about this install, never counts of your data:
  which milestones it has reached, which days of the last four weeks it
  was active, which tools it has used and where its first import came
  from. `oh request send` counts one send by protocol.
- **The privacy policy, effective October 25, 2026** — names the five
  event families and the state facts instead of a shape count, says
  that raw events are kept thirteen months and aggregates after, and
  describes the outbox: an undelivered envelope waits in the config
  directory for the next command and goes with the switch.

## Requests

- **Path parameters** — a saved request whose URL names `:name`
  segments sends with its Path Parameters rows substituted before the
  query, on `oh request send` and in runs alike; a row without a value
  sends as written.
