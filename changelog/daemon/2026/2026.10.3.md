## Sync

- **In order, and nothing lost** — the hub serializes each
  connection's change frames on a per-connection tail in arrival order,
  so a peer's burst flushed on reconnect applies as the peer made it
  instead of racing onto the entity lock and timing out below the
  hub's vector. The hub's catch-up walk pages the log by key and never
  holds a statement open while another peer writes on the same handle,
  which lost envelopes to a busy connection; the outbound drain reads
  its rows before its first yield for the same reason.
- **Every workspace boots from its log** — the workspace list and every
  per-workspace service hydrate by replaying the durable log at
  startup, behind one gate every reader awaits; a change already in the
  log is never committed twice, and a boot over a settled log appends
  nothing. The whole scope is replayed regardless of the branch that
  stamped a row, so a workspace bound to git boots into the state it
  held at shutdown rather than the trunk's, and the tree-wins sweep
  stops rewriting the working tree from a state the host never held.
- **Granted once, streamed once** — the row-filtered join resumes from
  the vector a member presents and streams the full history only of the
  workspaces that member was granted and has not yet received; a
  revoke clears the mark. A host bootstrapped from a snapshot records
  what the snapshot covered, so its next join streams only the delta
  instead of re-sending the whole workspace.
- **A container paused on 2026.8.x and unpaused later no longer comes
  back paused** — the old path-keyed pause markers retire or re-key
  once at boot.

## Sends

- **Path parameters** — a request whose URL names `:name` segments
  resolves its Path Parameters rows before the query on every send the
  server resolves itself (CLI runs, MCP, chains); scripts read the
  resolved rows; a row without a value sends as written.
