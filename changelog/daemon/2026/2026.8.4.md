## Configuration

- **`ohd install` saves its flags to `daemon.json`** — the config file
  is now the single source of truth: `status`, `show-token`, and the
  server itself all read the same configuration, so `ohd status` can
  no longer report a different bind than the one you installed with.
  Re-run `install` with new flags at any time to reconfigure; omitted
  flags keep their saved values, and the new `--no-trusted-proxy` /
  `--no-allow-insecure-lan` flags clear a previously saved setting.
- **New `ohd restart`** — restarts the installed service so a changed
  configuration (or an upgraded binary) takes effect. `ohd start` on
  an already-running service is a no-op, and `install` now tells you
  so: when the service is running it points at `ohd restart` instead.
- **`ohd show-token` prints the LAN join URLs** whenever the server is
  configured to listen on `0.0.0.0`, instead of claiming the server is
  loopback-only.
- **`ohd config set` points the right way** — bind and network flags
  aren't settings, and the errors now say so: `config set` lists its
  settable keys and directs bind changes to `ohd install`, instead of
  a circular error about a change the command could not make.

## Fixes

- **No more startup SQLite warning** — every `ohd` command printed
  Node's "SQLite is an experimental feature" warning at startup even
  though the server never uses that module by default; the module is
  now loaded only if it is ever actually needed, and the warning is
  gone.
