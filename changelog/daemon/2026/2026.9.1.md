## GraphQL on the server

- **Queries and mutations for the clients it serves** — a forwarded
  GraphQL request compiles once into its single POST and runs the
  exact leg an HTTP request runs: the collection's authorization
  pool, inherited settings, scripts, trusted certificates, proxy and
  dial settings all apply. The answer is an HTTP snapshot with the
  GraphQL errors and extensions read beside it.
- **Subscriptions** — the server dials a forwarded `subscription` over
  the WebSocket plane with the `graphql-transport-ws` client mounted,
  under the session's TLS and dial settings, and streams its events
  back to the tab that opened it.
- **Introspection through the server** — a request's schema loads
  from its endpoint through the same leg, so the request's own
  authorization, headers and settings sign the introspection query.
- **MCP tools and `oh`** — `requests_list` rows GraphQL requests
  (`kind: "graphql"`, sent as one POST) beside HTTP ones, and
  `requests_send`, `requests_authorize` and
  `requests_authorize_status` take either kind by uid, so `oh request
  run` and agent clients run a GraphQL request like any other.
  Workflow steps run them too.
