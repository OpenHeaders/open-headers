## Git — the bound folder

- **Pull and merge, value by value** — the other side's change is laid
  over the workspace instead of taking each touched document whole;
  two edits to different values of one item both stand, and a value
  both sides changed is refused with nothing written until a client
  answers it. The pass commits only the files it wrote; uncommitted
  work elsewhere stays uncommitted.
- **Files of your own travel** — a readme, a script or a note kept in
  the folder is carried by a pull and a merge, and a peer's edit to a
  request no longer clears its body and scripts.
- **Secrets are never committed** — the vault and secret files are
  kept out of every git command of the server's, whatever an ignore
  file says; an environment's secret rows survive a pull.
- **Links and paths** — nothing is read, written or removed through a
  symbolic link, a path no folder can hold is refused, and `.oh` is
  always a real directory.
- **While another git process writes** the server waits — it writes no
  file over git's, reads no half-written file, and refuses a pass on a
  busy index with nothing written. A commit, a branch or a tag made in
  a terminal is heard without a restart.
- **What was not taken in** — one row per cause, naming the field: a
  collection that does not read, an item outside any collection, a
  copied folder, a file over 16 MiB.
- **Faster** — a commit's files are read through one git process: a
  pull of one renamed request among 2,000 went from over three minutes
  to under six seconds.

## Sync

- **A deleted item can be restored under its id** — an item whose file
  returns in the bound folder is restored on every client; an edit or
  a plain create never brings a deleted item back. Clients are told
  when a workspace's checked-out branch changes.
