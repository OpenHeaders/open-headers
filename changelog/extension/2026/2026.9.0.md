## MQTT

- **MQTT requests** — a new request kind in the workbench tab beside
  HTTP, WebSocket and gRPC. From the browser, connect to a broker over
  `ws://` or `wss://`, subscribe to topics and publish messages;
  `mqtt://` and `mqtts://` sessions run on the desktop app or
  OpenHeaders Server, and the editor says so — switch to `ws://` or
  `wss://` to connect from the tab. MQTT 5.0 is the default and
  3.1.1 a switch.
- **Topics, compose and saved messages** — a topics table with per-row
  QoS, a subscribe toggle and subscription options; message compose
  with properties and text, JSON, base64 or hexadecimal payloads; a
  last-will tab; and a saved-messages rail that keeps named messages
  per request and saves a timeline frame as a new one.
- **Auto-reconnect** — a dropped session redials with exponential
  backoff up to an attempt cap, replays the wanted subscriptions and
  re-sends unacknowledged QoS 1 and 2 publishes, with *Reconnect now*
  while it waits.
- **Settings and timeline** — keep-alive, connect timeout, clean
  start, session expiry, receive and packet maximums, topic aliases;
  every knob's (i) lights an example CONNECT and SUBSCRIBE packet. The
  timeline shows connected, subscribed, published, received and
  disconnected rows with the packet's facts behind a chevron and a
  hexdump toggle on any payload.

## Authorization

- **Five new types** — **Hawk**, **JWT Bearer** (a fresh token
  minted per send from a secret or a private key, all twelve HS/RS/PS/ES
  families), **HTTP Message Signatures** (RFC 9421 with Content-Digest),
  **Akamai EdgeGrid** and **ASAP (Atlassian)** join the type list.
  Every signer runs in the browser over the final request shape at
  send time.
- **OAuth 2.0 grants and bindings** — the **Device Code** grant (the
  user code, the verification URL and a countdown sit in the Token
  group while the extension polls), the **JWT Bearer** grant, JWT
  client authentication (`private_key_jwt` and `client_secret_jwt`),
  **DPoP** token binding, a **Header Prefix** that wins over the token
  type, and a per-row *Send In* on the extra token and refresh
  parameters. Client credentials, password and JWT Bearer tokens renew
  silently on send once they expire.
- **OpenID discovery** — paste an issuer URL or a well-known URL and
  *Discover* fills the endpoints from the provider's metadata and
  flags the picks the provider does not list.
- **OAuth 1.0** — seven signature methods including the RSA family
  with a PEM private key, and the request body hash extension.
- **AWS Signature v4** — every outgoing header is signed except the
  SDKs' unsigned set; a query (presigned URL) mode; service and region
  derived from an AWS hostname when left blank.
- **Auth forms** — every type reads as collapsible groups with an (i)
  on every row that lights the matching token of that type's example
  wire shape; the type picker groups credential schemes, vendor
  signatures and No Auth behind dividers.
- **WebSocket, gRPC and MQTT requests carry their own credential** —
  WebSocket accepts basic, API key, OAuth 2.0, JWT Bearer and a signed
  AWS URL; gRPC basic, API key, OAuth 2.0 and JWT Bearer; MQTT basic.
  A credential the kind cannot carry in the browser is refused by
  name, never sent as nothing.

## Collections and folders

- **Authorization pools** — a collection or folder holds named
  authorization entries with a default and an optional *Apply to
  host* scope; a request set to *Inherit* resolves the nearest
  default or names any ancestor entry, and its Authorization tab
  shows the resolved entry's form inert with its source. The Headers
  and Params tabs describe the effective authorization and lock the
  generated row.
- **Inherited settings** — a *Settings* section on every collection
  and folder with HTTP, WebSocket, MQTT and gRPC sub-tabs; a request's
  Settings tab shows inherited values as placeholders, reads
  *Inherited from* or *Overrides* with the shadowed value, and *Reset*
  returns a knob to inherit. The response strip's *Inherited
  settings* tag names each knob and its level.
- **Scripts on containers** — every hook of every request kind on the
  container's Scripts section, and *Runs after N scripts* on the
  request's tab naming the ancestor levels; the response strip's
  *Scripts* tag lists every level that ran.
- **One container editor** — Overview · Authorization · Scripts ·
  Settings · Variables sections on one tab.
- **Deleting a collection or folder removes everything inside it** —
  requests of every kind, nested folders and every request's
  examples; a moved folder keeps taking new children and renames from
  the breadcrumb.

## Sidebar

- **Drag and drop** — move requests, folders and collections, or a
  multi-selection, by dragging with a placeholder that shows the
  landing spot; Alt+Arrow moves the focused row; folders and requests
  share one order that survives a restart.
- **Multi-select** — Cmd/Ctrl+click toggles any row, Shift+click
  ranges from the anchor; the selection drags as one.
- **Indent guides** — a guide per ancestor level while the tree is
  hovered, with a toggle under the panel options' Appearance submenu;
  panel options persist.
- **Tree rows** — short prefix tags per kind in one column, an
  *Add request* / *Add folder* scaffold in an expanded empty folder,
  and create menus that nest the kinds as a badge plus name.

## Browser Interceptor

- **Paused rules follow their container** — pausing a collection or
  folder is keyed to the container itself, so the pause survives a
  move or a rename; older path-keyed pauses migrate on first load.

## Session scripts

- **WebSocket, MQTT and gRPC hooks** — a Scripts tab per session kind
  with *Before connect*, *Before send* / *Before publish* / *Before
  invoke*, *On message* and *After close* hooks; scripts can rewrite
  or drop messages, send on the open session and share one
  `oh.session` object for its lifetime. The session pane gains a
  Scripts view with the console and tests, and the timeline a row per
  script mark with the hook's lifecycle card.
- **Firefox** — Firefox ships no script sandbox page, so session
  hooks do not run there; the session runs without them.

## WebSocket

- **URL and params** — the address row is the URL alone; a Params
  tab syncs with the query string both ways; Socket.IO's namespace is
  the URL path and its handshake path is a setting.
- **Handshake headers** — the browser's own auto-generated rows show
  behind the shared toggle, and a custom row the browser will not
  send is struck through with the reason.
- **Binary frames** — send a frame from base64 or hexadecimal text.
- **Saved messages** — the same rail as MQTT.
- **Timeline** — the connected row expands to the handshake facts,
  the disconnected row opens on the close code with its RFC 6455
  meaning, message rows reveal copy and info on hover, and a viewer
  toolbar offers format, wrap, hexdump and find. Socket.IO heartbeat
  and handshake frames hide by default.
- **Resilience** — auto-reconnect with period, attempt cap and
  backoff, an idle timeout, a heartbeat message and a maximum inbound
  message size; Socket.IO revision v5 or v4 and an ack timeout.
- **Session state** — *Cancel* while connecting, *Disconnect* once
  open; a cancelled attempt settles as aborted; the pill's hover
  opens the connection details; the editor's connect-time tabs
  freeze while a session is in flight.

## gRPC

- **Failures inside the pane** — an error-tinted timeline row with a
  classified hover; sent and received metadata rows; an authority
  override, a response size limit and *Include default values* as a
  response view choice.

## Every request kind

- **One Spec tab** — OpenAPI for HTTP with per-field *Apply*, a
  request-level OpenAPI link, AsyncAPI for WebSocket and MQTT, the
  service definition for gRPC; *Go to Specs* when none is linked.
- **TLS, dial and runtime rows on every settings tab** — verification,
  a client certificate, TLS window, cipher suites, SNI, resolve-to
  address and per-request proxy rows in one order across the kinds,
  each honest about what the browser cannot do, and a runtime-managed
  sheet listing what the browser decides for you.
- **Settings (i) cards** — every Settings tab's (i) opens an example
  send, session or call with the knobs lit token by token.

## Settings

- **A settings tree** — a full-height sidebar with search, bold roots
  and their pages: Appearance & Behavior, Editor, API Requests,
  Browser Interceptor, Keyboard, Version Control, Tools, Connectivity
  and Application. The page title is the path and the *Modified*
  filter is a tag inside the search.
- **Pages grouped into sections** — every page reads as titled
  sections on one field grid; row labels drop the context their
  headers carry; Backend splits into Connections, Server, Desktop
  Pairing and Reliability.
- **About** — a definition-list layout and a bundled open-source
  software listing.

## Look and feel

- **Popup hover lag is gone** — the action popup no longer realigns
  every mounted trigger on each resize tick, and its fixed-size shell
  no longer forces a double layout of the whole surface.
- **Smooth resizes** — the workbench shell is one layout grid; the
  rails stay on screen at any width.
- **Dark theme** — popovers, dropdowns and tooltips lose their white
  halo; session pills take the status chip's tones.

## Fixes

- **A user `Authorization` row is replaced, not merged** — basic,
  bearer, API-key and OAuth 2.0 headers replace a same-name header
  row instead of comma-joining with it; the Headers tab's
  struck-through row now tells the truth.
- **A request with only a proxy URL uses that proxy** — a request
  carrying a proxy URL and no mode silently went direct.
- **Wheel over embedded editors** — an expanded timeline row's
  editor no longer pins the page under the pointer.
