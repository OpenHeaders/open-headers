## Requests

- **Path parameters** — a request's URL names its parameters as
  `:name` segments (a literal suffix such as `:id.json` is allowed), and
  the Params tab gains a **Path Parameters** table derived from the URL:
  a locked **Name** column, a value that may use `{{variables}}`, and a
  description. Values are substituted before the query is built, the
  variable scanner and the request fingerprint see them, and scripts
  read the resolved rows. A row without a value reads *unresolved* on
  the URL bar's dot, the Params tab and the sidebar badge, and sends as
  written. The `:name` token in the URL bar paints like a reference and
  opens its own hover card; the Params headings carry an *(i)* card;
  the empty state asks for a `/:name` segment in the path.
- **Imports speak path parameters** — the OpenAPI, collection-file and
  folder-format importers emit `:name` URLs with the declared rows,
  and no longer inline example values or seed collection variables for
  them. The spec importer fills a row from the example, the default or
  the first enum value with its description, and notes an undeclared
  template, a non-required declaration and an unsupported
  serialization. Captured examples, the landing loop and **Save
  Response** carry the rows too.
- **The Spec tab and the Update dialog converge instead of rewriting**
  — a `{{name}}` whole-segment and a `:name` segment at the same
  position read as one operation, so a collection generated before
  path parameters moves to the `:name` form through your own apply as
  ONE change naming the URL and the path parameters — never a silent
  rewrite, never a remove plus an add. The GraphQL convert writes the
  rows into the URL as their values read, or refuses by name.
- **Unresolved variables on every editor** — the MQTT, WebSocket, gRPC
  and GraphQL editors now read the footer pill, the tab dots and the
  target row's status from the same per-section scan the HTTP editor
  uses, under the version and flavor lenses; the Variable Scope panel
  walks every request kind. The HTTP editor's Settings tab flags an
  unresolved SNI override.
- **Dirty marks** — the count badge on an editor tab only ever counts,
  in the neutral fill; one dot beside it reads red for unresolved,
  salmon for unsaved and neutral for has-content, on light and dark
  variants alike.
- **Smaller things** — a `{{ref}}` the editor split across tokens
  paints as one box; the URL bars share one placeholder idiom (*Enter
  URL*, or *Enter server URL* on WebSocket and MQTT; HTTP keeps *Enter
  URL or paste text*); the key/value grids' hairlines read the
  secondary fill and the focused cell's ring stands a step above; a
  locked key cell stands as tall as a query row; the gRPC TLS toggle and
  the MQTT version select open their tooltips downward, away from the
  title bar.

## Result panes

- **The send pulse** — one bar on the leading edge of every result
  pane sweeps while a send is in flight and lands in the status pill's
  tone. A stream is a session: an SSE response, a gRPC stream or a
  subscription rests on its tint from the head, sweeps one pass per
  message or publish, and lands by whose doing the end was — your own
  **Stop** or **Disconnect** neutral, the peer's close a warning, a
  refused message or a severed connection red. A MQTT CONNACK or a
  WebSocket handshake lands green; a GraphQL subscription lands blue
  once subscribed and green on the server's complete. The empty states
  drop the spinner the pulse now carries.
- **Stop reads as a stop** — a gRPC Stop before the head is the neutral
  stopped row on the stream timeline and *1 CANCELLED* with the stop
  message on the unary pane, not a failure; a failed After-response
  assertion paints the landing red.
- **Clear actions** wear the trash icon in place of the broom on the
  response panel, the SSE list and the WebSocket, MQTT and gRPC
  timelines; the lifecycle pill's Unresolved red reads muted on dark
  themes.

## Sessions

- **TOTP codes across a session** — a `{{totp}}` reference in a
  WebSocket, MQTT or gRPC session is gated before the dial and again
  before every write, with the code recorded when the session opens,
  when the CONNACK or the response head lands and after each write; a
  code still inside its window refuses the step before the wire, and a
  reconnect neither asks for nor records a new one. Connect and each
  message resolve as their own batch.
- **MQTT unsubscribe names the row** — toggling a subscription off
  unsubscribes exactly the filter it went up with: nothing re-resolves
  and no TOTP code is spent on an UNSUBSCRIBE. A live-subscribed row's
  filter cell reads disabled.

## Sync

- **Every store boots from its log** — the workspace list and every
  per-workspace store hydrate by replaying the durable log at startup
  behind one gate every reader awaits; a change already in the log is
  never applied twice, and a boot over a settled log writes nothing.
  The active workspace is remembered per app and never replicated.
- **A workspace bound to git boots into the state it held at shutdown**,
  not the trunk's, so the tree-wins sweep stops rewriting the working
  tree from a state this app never held.
- **A container paused on 2026.8.x and unpaused later no longer comes
  back paused** — the old path-keyed pause markers retire or re-key
  once at boot.
- **The sync hub applies in order and loses nothing** — a peer's frames
  apply in the order they arrived, so a burst flushed on reconnect
  lands whole; the hub's catch-up walk pages the log instead of holding
  a statement open while another peer writes, which lost envelopes on
  a busy connection; a host bootstrapped from a snapshot presents what
  the snapshot covered and the next join streams only the delta; a
  member granted a workspace receives its full history once, and a
  revoke clears that mark.

## Appearance

- **The window frame follows your theme** — on Windows and Linux the
  title-bar overlay and the **Menu** button's popup read in the app's
  theme from the first paint, and the frame's background is bound to
  the saved theme before the window shows. The **Menu** tooltip closes
  with the native menu.
- **Light themes keep a light success tint** — status tags no longer
  take the muddy wash a dark seed derives; the default light variant
  pins a darker success green.
- **The status and Add-ons popovers** — the status popover's rows sit
  in titled groups (*API Requests*, *Application*, the sync layers), in
  a body sized to its content; the **Add-ons** popover groups its rows
  by place — one row per connected browser extension wearing its
  browser's logo and name, the desktop row with the host OS mark, the
  server row with the bound Org's icon, the CLI and MCP rows with their
  own marks. The in-app docs follow.

## Help and diagnostics

- **A saved download gets a toast** — *Saved <file>* with **Show in
  folder** on a balloon and on the notification timeline, an
  interrupted save warns, a cancelled dialog says nothing; the toast
  shows on a crashed window too.
- **The diagnostic bundle is anonymized** — every gathered file is
  redacted on its way into the archive: stack frames keep only file and
  position, the folders the app knows (home, the app, its data, its
  logs, each bound workspace) become bracketed placeholders, any other
  path under your home or a temporary folder collapses, URL credentials,
  credential-named query values and e-mail addresses go; the bundled log
  is cut to this launch and the one before. The action now reads
  **Download anonymized diagnostic bundle…** and the README states what
  was removed.
- **Reporting** — the report dialog requires a title and a description,
  with the Markdown note under each field; the crash page offers
  **Report Issue** (seeded with the error) and **Community Chat** in
  place of Copy details and Open logs folder, and the crash survives
  Reload — the reloaded timeline offers the same two on a card. Report
  details name frames by basename and position only. The pending-crash
  card is no longer sticky, and a contained error's button reads
  **Reload**.

## Usage counting

- **An install-state block joins the envelope** — coarse facts about
  this install, never counts of your data: which milestones it has
  reached, which days of the last four weeks it was active, which tools
  it has used, where its first import came from, whether it has shared
  a workspace locally, and the setup's size class — rules and saved
  requests as ranges, how workspaces are kept (`local`, `server` or
  `git`), the role and team size held on a server, and the plan. Five
  event families gain shapes: a send by protocol, a limit reached (seats,
  service accounts, rule cap), a share sent on a grant, a share accepted
  once per Org on a first join over the network, and the milestone
  itself.
- **The privacy policy, effective October 25, 2026** — names the five
  event families and the state facts instead of a shape count, says
  that raw events are kept thirteen months and aggregates after, and
  says plainly what can and cannot be linked; the wire-transparency
  document carries the envelope and a column-by-column table of what
  the warehouse keeps. The switches moved to Settings › Application ›
  About › Privacy, and **Support** sits above **Open-source software**
  there.
