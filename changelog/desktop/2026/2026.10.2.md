## Resilience

- **An error is contained where it happens** — a tab or tool window
  that fails shows *This tab hit an error* or *This tool window hit an
  error* with **Retry**, **Close tab** or **Hide window**, and the rest
  of the app keeps working; a failed tab's close guard no longer offers
  a Save it cannot make. An error the whole window cannot recover from
  shows one page in the app's theme — *Reload to continue — your data
  is safe* — with **Reload**, **Copy details** (a green check confirms
  the copy) and **Open logs folder**. Every failure reaches the log
  once: one line, the frames under it.
- **The window supervisor** — a window whose renderer dies is reopened
  once; a second crash asks **Reopen**, **Open Logs**, **Restart
  Without Hardware Acceleration** or **Quit**, and a window that stops
  responding asks **Keep Waiting**, **Reopen** or **Quit**. A graphics
  process that crashed twice in a session offers the restart without
  hardware acceleration, and the application menu turns it back on. A
  reopen you asked for never counts toward the crash loop, Return and
  Escape have distinct roles on both dialogs, an exit that was not clean
  is known at the next launch, and a helper process that dies is logged
  with its reason.
- **An application menu button on Windows and Linux** — the frameless
  window hides the native menu bar, so **Menu** in the top bar opens
  the same menu.

## Crash and error reports

- **A second anonymous channel, one switch of its own** — Settings ›
  General › Privacy gains **Crash and error reports** beside
  **Anonymous usage counting**, each independent of the other. When
  the app crashes or hits an error it did not expect, a report says
  what kind of error it was and where in the app's own code it
  happened: error class names, template ids (which standard engine
  message it matched, never its text) and positions in the app's own
  files. No message and no install identifier — the random per-launch
  session id is all that groups reports — and nothing from a request,
  a rule, a script or a path on your machine can be expressed, because
  every string on the channel must match a fixed grammar. The same
  failure from the same place folds into one row per process and
  surface it fired in.
- **Readable byte for byte** — **View reports** opens the session
  inspector, now *Telemetry this session* with **Usage events** and
  **Error reports** as two tabs, each report exactly as sent or as
  suppressed. Turning the switch off holds reports already recorded on
  this device: they leave only if the switch goes back on in the same
  session, and are discarded when the app closes; the usage switch
  keeps discarding as before.
- **The privacy policy, effective October 19, 2026** — names the
  channel in its sharing, endpoint and transparency lines; the
  wire-transparency document carries the envelope and the grammar
  table.

## Usage counting

- **Five coarse facts join the envelope** — the CPU architecture
  (`x64`, `arm64`, or `x64` running on an `arm64` machine), the
  operating-system major (macOS 15, Windows 11 — never a build
  number), whether this desktop is paired with the browser extension,
  how the install keeps its workspaces (`local`, `server` or `git` —
  never where) and a fourteenth event: the size class an in-app surface
  opened at (*at least 800 pixels wide*, never a size). The policy and
  the wire document list each.

## Help

- **The Help menu in four groups** — learn: **Documentation**,
  **Keyboard Shortcuts**, **Release Notes**; ask or tell us: **Report
  Issue**, **Feature Request**, **Chat with Us on Discord**; diagnose:
  **Save Diagnostics…**, **Open Logs Folder**; legal: **License
  Agreement**, **Privacy Policy**. On macOS the Help search field
  knows the menu.
- **Report Issue and Feature Request** — a dialog with a title and one
  description (the steps to reproduce for a bug, the workflow and the
  behavior you would like for a feature; Markdown welcome) and the
  system facts as a table behind **show**, with a checkbox to leave
  them out. **Preview on GitHub** opens a new issue with the title and
  one composed body; nothing is posted until you submit it there, and
  logs never ride the link — **Save bundle…** sits beside the notice.
  Your text is kept whole: when the link runs long the facts are
  trimmed first (GPU rows, then displays, then the block) and the
  dialog says so; a text too long for any link asks you to shorten it
  here and add the rest on GitHub. The dialog also opens from Settings ›
  About › Support (**Report…**, **Request…**) and from the notification
  timeline's **Bug Report or Feature Request** card; a **Community
  Chat** card replaces the website nudge.
- **The diagnostic bundle** — Settings › Data › Diagnostics gains
  **Diagnostic Bundle › Save bundle…** (Help › Save Diagnostics… is the
  same): one ZIP with the log files, the diagnostic log, the status
  snapshot, this session's telemetry events and crash reports, your
  settings and the system facts, saved where you choose and sent
  nowhere.

## Fixes

- **A beta downloads like a stable** — beta builds are compressed the
  way stable builds are, so a beta is the stable's size instead of
  three times it, and the updater can download the difference between
  the two instead of the whole file. The update row's bar no longer
  shows a finished check while the download is still being verified.
- **JSON diagnostics wait for the JSON mode** — the first validation of
  a JSON body no longer runs before the language mode is set up, so the
  first pass is never rejected.
- **In-app docs** — two diagrams with a blinking terminal cursor kept
  the window repainting while the Docs tab was shown; the cursors are
  static.
