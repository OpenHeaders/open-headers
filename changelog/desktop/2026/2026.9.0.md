## MQTT

- **MQTT requests** — a new request kind beside HTTP, WebSocket and
  gRPC. Connect to a broker over `mqtt://`, `mqtts://`, `ws://` or
  `wss://`, subscribe to topics and publish messages from one editor.
  MQTT 5.0 is the default and 3.1.1 is a switch; a 5.0 request against
  a 3.1.1-only broker is refused with the broker's own words.
- **Topics table** — every subscription row carries its own QoS,
  a subscribe toggle and an options popover (no-local, retain as
  published, retain handling, a subscription identifier, user
  properties). Subscribed topics show as coloured chips on the
  session pane, and a live QoS edit re-subscribes the row.
- **Message compose** — topic, QoS, retain and the payload in text,
  JSON, base64 or hexadecimal, with message properties (content type,
  response topic, correlation data, expiry, user properties) behind a
  gear. A last-will message with its own delay, properties and
  payload sits on its own tab.
- **Saved messages** — a collapsible rail beside the compose editor
  keeps named messages per request; click to load, rename inline,
  edit through to the selected row, and save a timeline frame as a
  new message.
- **Auto-reconnect** — a dropped session redials on a period with
  exponential backoff and jitter, up to an attempt cap, replays the
  wanted subscriptions when the broker kept none, re-sends unacknowledged
  QoS 1 and 2 publishes with the duplicate flag when it did, and
  offers **Reconnect now** while it waits. The timeline logs every
  loss, attempt and reconnection with the new connack facts.
- **Settings tab** — keep-alive, connect timeout (30 s by default),
  clean start and session expiry, receive maximum, maximum packet
  size, topic alias maximum, request response and problem
  information; TLS with a client certificate from the vault, an SNI
  server name and an ALPN protocol; basic authentication on the
  Authorization tab. Every knob's (i) lights the matching field of an
  example CONNECT and SUBSCRIBE packet.
- **Timeline** — connected, subscribed, published, received,
  disconnected and error rows with the packet's facts behind a
  chevron, a hexdump toggle on any payload, and a cancel that settles
  a half-open attempt as aborted rather than failed.
- **Examples and specs** — Save Response mints MQTT examples, and
  generating a collection from an AsyncAPI document creates MQTT
  requests with their topics and example messages.

## Authorization

- **Five new types** — **Hawk**, **JWT Bearer** (a fresh token
  minted and signed per send from a secret or a private key, all
  twelve HS/RS/PS/ES families), **HTTP Message Signatures**
  (RFC 9421 with Content-Digest per RFC 9530), **Akamai EdgeGrid** and
  **ASAP (Atlassian)** join the type list. Every signer computes over
  the final request shape at send time, on the desktop and on the
  server alike.
- **OAuth 2.0 on the desktop works end to end** — *Get new access
  token*, the callback URL, refresh and revoke were answered only by
  the browser extension before; the desktop app answered "RPC not
  implemented" and the callback sat on *Detecting…*. The authorization
  code flow now opens your system browser and returns to the app on a
  loopback callback URL on the backend port (register
  `http://127.0.0.1:<port>/oauth/callback` with your provider), and
  the app comes to the front the moment the callback lands.
- **OAuth 2.0 grants and bindings** — the **Device Code** grant
  (approve on any device; the user code, the verification URL and a
  countdown sit in the Token group while the app polls), the
  **JWT Bearer** grant, JWT client authentication (`private_key_jwt`
  and `client_secret_jwt`) beside body and Basic, **DPoP** token
  binding with a proof algorithm of your choice, a **Header Prefix**
  that wins over the token type, and a per-row *Send In* on the extra
  token and refresh parameters (body, header or query). Client
  credentials, password and JWT Bearer tokens renew silently on send
  once they expire.
- **OpenID discovery** — paste an issuer URL or a well-known URL and
  *Discover* fills the endpoints from the provider's metadata document
  and tells you which of your picks the provider does not list.
- **OAuth 1.0** — seven signature methods (HMAC-SHA1/256/512,
  RSA-SHA1/256/512 with a PEM private key, PLAINTEXT) and the
  request body hash extension.
- **AWS Signature v4** — every outgoing header is signed except the
  SDKs' unsigned set, so `x-amz-*` rows on an S3 PUT verify; a query
  (presigned URL) mode; service and region derived from an AWS
  hostname when left blank.
- **Digest** — an opt-out of the automatic challenge retry, so the
  401 and its challenge surface verbatim.
- **Auth forms** — every type reads as collapsible groups
  (Credentials · Token · Signing · Delivery …) with an (i) on every
  row that lights the matching token of that type's example wire
  shape; the type picker groups credential schemes, vendor signatures
  and No Auth behind dividers.
- **WebSocket, gRPC and MQTT requests carry their own credential** —
  WebSocket accepts basic, API key, OAuth 2.0, JWT Bearer and a
  signed AWS URL; gRPC basic, API key, OAuth 2.0 and JWT Bearer; MQTT
  basic. A credential the kind cannot carry is refused by name, never
  sent as nothing.

## Collections and folders

- **Authorization pools** — a collection or folder holds named
  authorization entries with a default and an optional *Apply to
  host* scope. A request set to *Inherit* resolves the nearest
  default, or names any ancestor entry. A folder shows the inherited
  entry read-only with *Edit in parent*, *Override* and *Reset*; the
  request's Authorization tab shows the resolved entry's real form,
  inert, with its source. The Headers and Params tabs describe the
  effective authorization and lock the generated row — the
  Authorization tab is the way in. The run's meta strip names which
  entry signed the send.
- **Inherited settings** — a fifth *Settings* section on every
  collection and folder with HTTP, WebSocket, MQTT and gRPC sub-tabs.
  A request's Settings tab shows inherited values as placeholders,
  reads *Inherited from <level>* or *Overrides <level>* with the
  shadowed value, lists every level that sets the knob when more than
  one does, and *Reset* returns a knob to inherit. Saving writes only
  the knobs you changed; the response strip's *Inherited settings*
  tag names each knob and its level.
- **Scripts on containers** — the Scripts section of a collection or
  folder carries every hook of every request kind, and a request's
  Scripts tab names the ancestor scripts that run ahead of it
  (*Runs after N scripts*, each a link). The response meta strip's
  *Scripts* tag lists every level that ran with its duration and the
  failing level's own error.
- **One container editor** — a collection or folder opens as one tab
  with Overview · Authorization · Scripts · Settings · Variables
  sections; *Add request* is the only action.
- **Deleting a collection or folder removes everything inside it** —
  requests of every kind, nested folders and every request's
  examples; a request dragged out first is spared. A folder moved to
  another collection keeps taking new children, deletes cleanly and
  renames from the breadcrumb.

## Sidebar

- **Drag and drop** — move requests, folders and collections, or a
  multi-selection, by dragging; a dashed placeholder shows where the
  drop lands and *n items moved* confirms it. Alt+Arrow moves the
  focused row. Folders and requests share one order, the order rides
  the git tree and survives a restart.
- **Multi-select** — Cmd/Ctrl+click toggles any row, Shift+click
  ranges from the anchor; the selection drags as one and *Export
  selected* folds to the rows that can export.
- **Indent guides** — a guide per ancestor level while the tree is
  hovered, the hovered row's parent lit; toggle them under the panel
  options' Appearance submenu. Panel options persist across restarts.
- **Tree rows** — request kinds wear short prefix tags in one column
  (`DEL`, `OPT`, `PTCH`, `WS`, `MQTT`…), an expanded empty folder
  offers *Add request* and *Add folder*, and every create menu nests
  the kinds as a badge plus name.
- **Pausing follows the container** — a paused collection or folder
  stays paused when it is moved or renamed; older path-keyed pauses
  migrate on first load.

## Session scripts

- **WebSocket, MQTT and gRPC hooks** — every session kind gains a
  Scripts tab with a hook per moment of the connection: *Before
  connect* (rewrite the URL, headers, subprotocols, client id,
  credentials, the will, subscriptions), *Before send* / *Before
  publish* / *Before invoke* (rewrite or drop the outgoing message),
  *On message* (read or mutate what arrived, or drop it), *After
  close*. Scripts can send on the open session from any hook, and
  share one `oh.session` object for the session's lifetime.
- **Session console and tests** — the session pane gains a Scripts
  view with the console and test results, a strip tag counting the
  hooks that ran, and a timeline row per script mark with the hook's
  (i) lifecycle card.
- **Snippets per hook** — every hook's snippet list is cut from its
  own API, and the rail's (i) opens the request kind's lifecycle as a
  card, one line per hook in wire order.

## WebSocket

- **URL and params** — the address row is the URL alone (no scheme
  lock, no flavour tag); a Params tab with key, value, description
  and bulk edit syncs with the query string both ways. Socket.IO's
  namespace is the URL path, and its handshake path is a setting.
- **Handshake headers** — the auto-generated rows (`Host`,
  `Connection`, `Upgrade`, the `Sec-WebSocket-*` trio, and the
  browser's own set when a browser dials) show behind the shared
  toggle with per-header hints.
- **Binary frames** — send a frame from base64 or hexadecimal text;
  a malformed payload names itself and gates Send. Examples capture
  the compose mode.
- **Saved messages** — the same rail as MQTT: named messages per
  request, saved from the compose editor or from a timeline frame.
- **Timeline** — the connected row expands to the handshake (request
  URL, method, status, both header sets); the disconnected row opens
  on the close verdict with the RFC 6455 phrase and the code's
  meaning; message rows reveal copy and info actions on hover; a
  toolbar over the framed viewer offers format, wrap, hexdump and
  find. Heartbeat and handshake frames on Socket.IO sessions hide by
  default (toggle from the sort menu).
- **Resilience** — auto-reconnect with period, attempt cap and
  backoff, an idle timeout that cuts a silent connection, a heartbeat
  message on an interval, a maximum inbound message size, and
  handshake redirects followed up to a cap on the desktop.
- **Socket.IO protocol** — pick revision v5 (default) or v4 for 1.x
  and 2.x servers, and set an ack timeout; a timed-out ack shows as
  its own timeline row.
- **Session state** — the Connect button reads *Cancel* while
  connecting and *Disconnect* once open; a cancelled attempt settles
  as aborted, not failed; the pill's hover opens a connection details
  sheet (peer, subprotocol, negotiated extensions); the editor's
  URL, params, auth, headers and settings freeze while a session is
  in flight, compose stays live.

## gRPC

- **Failures inside the pane** — a failed call renders as an
  error-tinted timeline row with a classified hover instead of an
  error wall; a connection lost after the headers names itself (a
  missing status, a GOAWAY, a reset) on the pane and the strip.
- **Metadata** — the request-sent row expands to the dispatched
  metadata; the connected row expands to the received metadata with a
  jump into the Metadata tab.
- **Settings** — an authority override, a keep-alive ping interval
  and timeout, a response size limit, and *Include default values* as
  a response view choice that fills absent presence-less fields.
- **Compose** — *Use example message*, *End streaming* and *Send
  message* sit on a bar below the editor.

## Every request kind

- **One Spec tab** — last after Settings on every editor: OpenAPI for
  HTTP (the linked document, the operation this request pairs with,
  the fields that differ with per-field *Apply* and *Apply all*), a
  request-level OpenAPI link beside the collection's, AsyncAPI for
  WebSocket and MQTT, the service definition for gRPC; an editor with
  no spec of its format offers *Go to Specs*.
- **TLS & trust on every settings tab** — verification, trusted
  certificates, a client certificate (mTLS) from the vault, a TLS
  version window, cipher suites and an SNI server name in one order
  on HTTP, WebSocket, gRPC and MQTT.
- **Dial rows on every settings tab** — resolve to address, proxy
  mode, proxy URL and proxy credentials per request, for sessions as
  for HTTP; an explicit conflict fails before the wire.
- **Runtime-managed sheet** — each editor lists what the dialing
  runtime decides for you (the permessage-deflate offer, HTTP/2 for
  gRPC, the browser's never-followed redirect…).
- **Settings (i) cards** — every Settings tab's (i) opens an example
  send, session or call with the tab's knobs lit token by token.
- **Auto-generated headers follow the dialing host** — the desktop
  lists the seven the HTTP client adds in wire order, each yielding
  to your own row; every dial identifies itself as OpenHeaders with
  the app version unless the request names its own user agent.

## Trusted certificates

- **Three trust scopes** — a **workspace** list of CA roots that
  syncs with the workspace and lives in the git tree, **this
  device's** pinned certificates, and an opt-in to the **operating
  system's** trust store. All three apply additively to every HTTP,
  WebSocket, gRPC and MQTT dial and to the proxy's upstream leg.
  Manage them under Settings › API Requests, and see the count on
  every editor's TLS rows.
- **Trust gesture** — a verification failure on any kind renders a
  *Trust certificate* offer that probes the presented chain, pins a
  self-signed anchor on this device or adds a CA root to the
  workspace, then resends or reconnects.
- **Network popover** — the response strip's globe tints green for a
  verified HTTPS send and red for an unverified one; the popover
  lists the hop, session and certificate facts and one warning row
  naming a self-signed certificate.

## Settings

- **A settings tree** — a full-height sidebar with search, bold roots
  and their pages: Appearance & Behavior, Editor, API Requests,
  Browser Interceptor, Keyboard, Version Control, Tools, Connectivity
  and Application. The page title is the path, descriptions live on
  the landing pages, and the *Modified* filter is a tag inside the
  search.
- **Pages grouped into sections** — every page reads as titled
  sections on one field grid with the info trigger beside the label;
  row labels drop the context their headers carry. Backend splits into
  Connections, Server, Desktop Pairing and Reliability; AI · MCP
  Server into Access and Clients; Git into Folder and Automation
  (operating the repository is the Git tool window's job); the Code
  Editor and Diff Viewer pages sit under Editor.
- **About** — the info rows align as a definition list and a bundled
  open-source software listing joins the page.

## OpenHeaders Server

- **Set up from the browser** — the first browser to open a fresh
  server creates the admin account; a remote browser presents the
  setup code the server printed at start. Sign-in is by email and
  password or single sign-on; the token field left the browser.
- **Roles** — server admin is a per-user role, a **guest** role and
  per-workspace visibility (private, internal, public) land, owners
  grant and revoke peers from the workspace's members modal, invited
  users arrive with their workspace access, a revoked user is evicted
  live, and **service accounts** (no login, data plane only) can be
  created from the console.
- **Public workspaces** — with the server's public-workspaces switch
  on, an owner can publish a read-only snapshot of a public workspace
  that anyone can open at `/public/<workspace>`; a review moment
  shows what the snapshot contains before it goes out.
- **Server Admin tool window** — per-domain tabs (Users, Devices,
  Git, Audit, Server) in one dock panel.

## Look and feel

- **Smooth window resizes** — the shell is one layout grid; resizing
  the window no longer judders and the rails stay on screen at any
  width.
- **Dark theme** — popovers, dropdowns and tooltips lose the white
  halo they cast in dark mode.
- **Session pills** — WebSocket, MQTT and gRPC states wear the HTTP
  status chip's pill: connected as success, connecting neutral,
  reconnecting warning, disconnected as error; the tree's WebSocket
  marks turn orange and every kind's mark has a dark-theme tint.

## Fixes

- **A request with only a proxy URL uses that proxy** — a request
  carrying a proxy URL and no mode (from the API, the CLI, imports or
  older saves) silently went direct; it now routes through the URL.
- **Wheel over embedded editors** — an expanded timeline row's
  editor no longer pins the page under the pointer; the wheel chains
  to the enclosing scroller at either edge.
- **Container sections size to their pane** — the Scripts and
  Authorization sections of a collection or folder ran past their
  parent by the padding.
- **Faster tab switches** — the workbench's tab context menu builds
  only while open and hidden tab bodies are memoized.
