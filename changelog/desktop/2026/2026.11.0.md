## Git window

- **A log over the whole history** — rows are read as you scroll, so a
  repository of any size opens at once. The graph colours each lane by
  its branch, lights a linear run under the pointer and folds it on a
  click, and the commits the current branch reaches wear a tint.
- **Filters and search** — the Branch, User and Paths filters take
  several values, keep a recent list and a **Favorites** scope; paths
  can be picked from a tree of the workspace. The text field applies on
  Enter and searches the whole history, with every match painted. No
  merges, first parent and the sort all keep the graph.
- **The commit menu** — Copy Revision Number, New Branch…, **New
  Tag…**, **Checkout Revision**, **Cherry-Pick**, **Revert Commit**,
  **Create Patch…** and Copy as Patch to Clipboard. Several commits
  select with Ctrl/Cmd and Shift and show their files as one set; a
  merge commit lists its changes against each parent.
- **Columns and labels** — author, hash, date and **GPG Signature**
  columns, a compact or a full reference view, references on the left,
  and *Today HH:MM* in your clock format. The same options sit under
  Settings › Version Control › Git › Log.
- **Branches** — a branch switcher in the top bar beside the workspace
  switcher, with **Update Workspace (Pull)**, **Push…**, recent
  branches and favorites; the branches pane stars favorites and shows
  incoming and outgoing counts. **Git Remotes** adds, edits and removes
  remotes.
- **The console** is a text view of every git command the app ran,
  with selection, copy and clear.
- **Changes made outside the app are heard** — a commit, a branch, a
  tag or a staged file from a terminal reaches the windows without a
  refresh. A rebase, merge, cherry-pick, revert or bisect started
  outside is named on the branch switcher with its own abort. A
  detached HEAD, a shallow clone and a linked worktree are recognised.

## Commit and push

- **Changes by what they belong to** — a **View Mode** switch,
  *Workspace* or *Files*, lists changes under their sections,
  collections and items by name, or as folders and files; the same
  switch sits on every changed-files tree.
- **Verbs over a selection** — the tree multi-selects; **Add to VCS**,
  **Delete…** and Add to .gitignore act on the selection, and
  **Rollback Changes** opens a dialog with the files checked. The
  counter reads what the commit would take.
- **The message box** previews earlier messages as you walk the
  history; with **Amend** on it shows the amended commit's author.
- **The Push window** — **Push…** and **Commit and Push** list the
  commits the remote lacks with their files. A rejected push offers to
  merge and push again; a push without permission can publish the work
  as a new branch; a rewritten remote raises a banner with its choices.
- **Open a clone as a workspace** — binding a folder that holds a
  teammate's workspace offers to open it as its own workspace.

## Pull, merge, cherry-pick and revert

- **Value by value** — the other side's change is laid over yours: two
  edits to different values of one item both stand. Where both sides
  changed the same value, a dialog names the files by workspace item
  and offers **Accept Incoming**, **Keep Mine** or **Review Conflicts**
  in the merge editor. Nothing is written until you answer.
- **Only the files the pass wrote are committed** — uncommitted work
  elsewhere stays uncommitted, and so does unfinished work in an item a
  pull changes. Where your work has to be committed first, the app
  asks, naming the files.
- **Your own files travel** — a readme, a script or a note kept in the
  folder is carried by a pull, a merge, a cherry-pick and a revert;
  where both sides changed one, you answer it or your version is kept
  and named.
- **Fixed** — a peer's edit to a request no longer clears its body and
  scripts; an environment's secret rows survive a pull.

## The bound folder

- **Secrets are never committed** — the vault and secret files are
  kept out of every commit whatever an ignore file says; `.gitignore`
  and `.gitattributes` are yours once they exist.
- **Links are never followed** — nothing is read, written or removed
  through a symbolic link. A link standing in an item's place is named
  on the Git card, and nothing is checked out while it stands.
- **While another git process writes** the app waits — it writes no
  file over git's, reads no half-written file, and says *Another Git
  process is using this repository* instead of failing.
- **A deleted item returns with its file** — a rollback, a revert, a
  branch switch, a stash pop or a pull that brings its file back
  restores it.
- **What was not taken in** — the Git card shows one row per cause: a
  collection that does not read, an item outside any collection, a
  copied folder, a file over 16 MiB, each naming the field at fault.
- **Faster pulls** — a pull of one renamed request among 2,000 went
  from over three minutes to under six seconds.

## Activity Monitor

- **A new tool window** — the app's own processes by name, each with
  its CPU, memory and an hour of history; a terminal tab, Git and the
  HTTP/3 helper open to what runs beneath them. CPU is a share of the
  whole machine.
- **Running** lists what the app keeps going in the background, each
  with an arrow to where it is managed. Nothing here leaves this
  device.

## Workbench

- Every tree shares one multi-selection (Ctrl/Cmd, Shift, Shift+arrows);
  Settings reopens on the page you left; a dark dialog has an edge.
- **Settings search** — every word narrows the results, matches are
  highlighted, and a long result list no longer freezes the window.
- **A Diagnostics menu** — the menu bar gains **Diagnostics**, beside
  Help. **Activity Monitor** opens the tool window, or brings it to the
  front where it is already open; **Download Anonymized Diagnostic
  Bundle…** and **Open Logs Folder** move there from Help.
- **Server Admin is now Administration** — the tool window, its tabs
  and every button that opens it; the role reads **Administrator**. Its
  rows are one line each and the row whose tab is open is marked; what
  each one covers is in the panel's (i). The **Server** row is gone
  from the desktop app — the build is under Settings › About.

## Platform

- **Windows on ARM** — a native ARM64 installer beside the x64 one;
  the updater takes the one for the machine.
- **Intel Macs and ARM Linux** — each build is now made on a machine of
  its own architecture; earlier ones could fail to start there. On
  Apple silicon, macOS no longer warns of Intel-only code in the app.
- Electron 44.10.0. Dependency updates close the open advisories:
  hono, body-parser, qs, fast-uri, follow-redirects and minimatch.
