## Secret managers

- **A Vault entry that lives in 1Password** — **Add secret…** in the
  Vault gains the kind *Secret Manager*: pick a connection and name the
  vault, the item and the field. The entry is referenced like any other
  (`{{vault.name}}`), but the value is fetched through the manager only
  when a request runs, is never written to this device and never
  appears in the editor, the Vault table, a copied command or a saved
  response. The row's chip reads the connection's standing on hover, and
  an (i) beside every field shows the provider's own example with the
  slice it describes lit.
- **Settings › Secret Managers** — one row per account this device
  reaches: provider, account, status, **Test**, edit and remove. A
  1Password connection names the account exactly as the 1Password app
  lists it and the lane it signs in by: the 1Password app on this device
  (its own approval prompt, biometric where you turned it on, asked
  again after its ten minutes of inactivity) or a service account whose
  token is read from `OP_SERVICE_ACCOUNT_TOKEN` at use time and never
  stored. The status reads what was seen — *Not tested* before any
  contact, *Connected* with its age after one, the moment and the
  approval window in the tooltip — and **Test** is a real round trip. A
  connection is a device setting: never synced, never a credential. The
  other managers on the picklist — Bitwarden Secrets Manager, this
  computer's credential store, AWS Secrets Manager, Azure Key Vault,
  HashiCorp Vault — read *not available on this device* until their
  providers ship.
- **Every refusal names its fix** — a locked or declined manager reads
  *authorization required* and the next send asks again; a reference
  the manager cannot satisfy reads *secret not found* in the vendor's
  own words (no vault matched, the field is not on the item, more than
  one match, an archived item); the app absent, or its SDK integration
  turned off, names the setting to turn on. Every send is a new attempt
  — a Test that was declined never makes a connection permanently
  unavailable. An error toast now stays six to ten seconds by its words
  and a click dismisses it.
- **Sessions too** — a WebSocket handshake header, a gRPC metadata pair
  or an MQTT message that names a secret-manager entry resolves at
  Connect or when the message goes; the timelines show
  `<hidden: a secret manager value>` where the value was while the
  capture keeps the bytes. A send to a server counts the secret-manager
  values that leave with it in the place popover's transit sentence.
- **For your paired browsers** — a browser paired with this app on the
  same machine resolves its secret-manager references through this app
  (list, Test and resolve ride the pairing; a change never does), so the
  1Password prompt appears here for a request sent from the extension.

## Sending

- **Send never blocks on an unresolved variable** — an `{{unknown}}`
  reference rides the wire as written. The response strip wears
  **Sent as written · N** with a popover listing each reference against
  its fix, the tab dots and the red dress keep saying it, and the
  response shows what the server made of the literal. Only a secret
  manager's typed failure refuses a send, naming every entry with its
  reason. **Copy as cURL / fetch** writes a secret-manager reference
  literally instead of refusing, and the toast says so.
- **Failures say what to check** — a classified failure (a name that
  does not resolve, a refused connection, TLS, a proxy leg, a pinned
  dial) shows the fact first and the advice under it in the secondary
  tone, on the response pane and on the WebSocket, MQTT and gRPC
  timelines' error rows. An MQTT refusal expands to the CONNACK the
  broker answered with.

## Scripts

- **Scripts read the send's own values** — `oh.variables.get` and
  `oh.vault.get` answer from the resolution the send resolved with: its
  collection, environment, step captures, TOTP codes and files, and a
  secret manager asked on first read. A TOTP code a script reads is the
  send's usage: a code still inside its window refuses the send before
  the wire, the same cooldown the templates have.
- **The Scripts tab speaks the API** — a `{{reference}}` in a script's
  source is never resolved, so the brace plane is off there; instead the
  string argument of `oh.variables.get('…')` and `oh.vault.get('…')`
  wears the variable dress, opens the completion list (vault entries
  alone for the vault lookup) and the hover readout, and a pick writes
  the bare name inside the quotes. Typing `oh.` lists the API alone —
  the language service no longer offers the browser window's handlers
  beside it, and every shipped snippet typechecks against the runtimes'
  real globals.

## Code editor

- **Variables inside bodies** — every `{{ref}}` in a JSON, XML, text or
  GraphQL body paints resolved or unresolved like the line inputs; `{{`
  opens the same picker (ranking, recents, the create row), hovering a
  reference opens the readout with edit and create, and a JSON body
  validates through a shadow in which each reference reads as a number
  — a `{{ref}}` is never a syntax error while a real error on line 7 is
  marked. The editor's own completions and hover pause while ours are
  open.
- **The Editor menu** — a last **Settings** row jumps to Editor › Code
  Editor; **Sticky scroll** is a knob, on by default, and the pinned
  header follows a paste or a delete-all at once; rows that are on
  carry the check mark alone. **Find**, **Replace** and **Format** show
  icon and name on every editor; Format stays in the row for every
  language, disabled with the reason where no formatter exists, and
  resolves on the click — a Text message that reads as JSON adopts the
  encoding on MQTT and WebSocket.
- **Pretty by default** — JSON and markup messages open formatted with
  a **Raw** toggle, and the markup formatter runs only over text that
  carries a tag, so a JSON payload read as HTML is no longer reflowed as
  prose.
- **The caret lands where you click on Windows** — the preset's web
  font is awaited before its glyph metrics are trusted; a value the
  host updates lands as one changed span with the selection kept,
  never a full replace that parks the caret at the end.

## Timelines and viewers

- **One strip on MQTT, WebSocket, gRPC and SSE** — a direction menu
  beside search whose trigger reads the filter in force (**Lifecycle
  only** keeps the connection story alone), topics or event names as a
  multi-select, the count reading *shown of total* under a filter,
  **Sort by**, a **View** menu holding the group and show knobs, a
  labeled **Clear**. Search is a lookup over every row — a lifecycle
  row's words, the text behind a chevron (the CONNACK, the handshake
  sheet, the metadata, a failure's guidance) and a message's full
  decoded text — and the no-match notice shows only when nothing at all
  matches.
- **MQTT grouping** — *Group by topic* and *Group by direction* (both
  at once make one header level), rows per group with *show older* at
  the older edge and a sticky group header; three new settings under
  API Requests.
- **One toolbar for read-only viewers** — the HTTP body's view picker
  (a language means Pretty; Raw, Hex and Base64 are the byte views) is
  shared by the timeline viewers and the SSE event viewer: picker,
  wrap, Find and a Viewer menu on every one, the HTTP body gaining
  Find. Copy and Size move to the row's hover cluster on every row.
- **Row anatomy** — lifecycle glyphs share the badge column on every
  timeline; the MQTT ended row reads *Disconnected from broker* with the
  glyph following the end; an empty payload reads *(empty)*; the SSE
  list gains the glyph column, a quiet badge for an unnamed event and
  the data previewed verbatim; the live meta strip's status pill
  carries its meaning popover from the moment the head lands.

## MQTT editor

- **Every field rides the variable plane** — the URL bar, the Message
  and Last Will topics, the gears' Response Topic, Correlation Data,
  Content Type and user properties, the topic filters: references
  paint, suggest and flag, and each resolves at CONNECT, PUBLISH or
  SUBSCRIBE. The WebSocket and gRPC editors, the gRPC authority, the
  GraphQL endpoint and the Socket.IO event name ride the same plane,
  and every editor reads `{{collection.X}}` through its owning
  collection instead of painting a resolvable reference red.
- **(i) cards everywhere** — every tab label, every Topics column
  header, every knob on the Message and Last Will bars and every gear
  closes with an (i) whose card lights the slice of a shared example
  session it shapes, with the packet as the kicker and the protocol
  versions it applies to as tags; the groups a card does not light fold
  to their opener line.
- **The gears speak the spec** — *Message properties*, *Will
  properties*, *Subscription options*, *Subscription properties* and
  *User properties* as titled sections marked with their packet; a
  knob off its default dots neutral and salmon while it differs from
  the saved request, with the Settings rows' undo on every one; a 3.1.1
  request leads with *V3.1.1: values saved, not sent. V5 only* and
  **Switch request to V5**.
- **Draft state** — the tabs and option rows dot the HTTP way (salmon
  unsaved, neutral has-content), Docs and Authorization gain the
  has-content tier, a Last Will typed before its topic saves as typed
  instead of vanishing on save, the encoding controls wear the body
  viewers' picker dress, and the Topics row gear reads icon +
  *Subscription*.

## Theme

- **Unsaved and Save follow the theme** — every unsaved mark and every
  Save-while-dirty button read a hard-coded salmon and brand orange
  that set a white label at 2.6:1 on the dark themes; each variant now
  pins its own tones, the light ones unchanged, the dark ones a deeper
  coral and orange white reads on. Has-content dots read in the neutral
  tone — a fact, not a call to action.

## Backup and Sync

- **One connection, one identity** — a server that answers under a
  different Org than its record is bound to (a wiped or reinstalled
  store, a build with its own data dir, a re-pointed address) is held
  under its connection row with **Accept new identity** or a dismissal
  on an authenticated wire, and replaced on a trust-by-process wire
  with the previous Org's workspaces kept as local copies. The
  placement row's popup sizes to its longest option, so the selected
  place no longer clips.
- **The last workspace of an Org stays** — it cannot be deleted from
  any device that sees it; the greyed delete says so on hover, and the
  row's icon actions carry tooltips.

## Fixes

- **Git sync** — git's auto-maintenance is pinned to the foreground so
  no detached git child writes to the repository after a command
  returned.
- **Dependencies** — advisories closed in the HTTP/3 helper's TLS
  library, the proxy's address parsing, the MCP SDK, the HTML
  sanitizer and the web framework the server embeds.
